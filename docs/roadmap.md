# Roadmap

## Correctness and trust work

1. **Done.** Replace the may-exit loop heuristic with a compact control-flow graph that distinguishes loop, switch, select, and labeled breaks. `internal/cfg` builds and dumps (`-dump cfg`) this graph, and `LL1002` now evaluates it via `internal/engine/cfg_verdict.go`: a persistent (cyclic) strongly-connected component with no edge reaching the function's exit, judged independently per component. This now applies to cross-package `go vet` targets too (fact schema version 3, `FunctionFact.LoopUnresolved`), not only same-package/closure ones — see `docs/cfg-migration-plan.md` for the phased plan and current status, and `docs/architecture.md` for how it fits the rest of the codebase. `LL1003`/`LL1004`/`LL1005` read a CFG too now (Phase 6, item 4 below), via their own separate mechanism rather than this one. Not yet done: `JoinObligation`/`Ownership` are still not exported as facts (see item 3 below), so a cross-package join/ownership question still has no CFG-based answer.
2. **Done.** Emit a low-noise user-visible `UNSUPPORTED` coverage outcome without turning every external goroutine target into a warning. Standalone text/JSON/SARIF output now distinguishes a clean result, a clean result with unsupported goroutine targets listed by file:line and reason, and a result where nothing lifecycle-relevant was recognized at all — see `docs/limitations.md`.
3. **Done**, via a direct frontend mechanism rather than by wiring up `internal/engine/dataflow_lattices.go`'s `Ownership` lattice. Track cancellation and group ownership through selected struct fields and constructor returns instead of treating every store as final discharge: `internal/frontend`'s `collectFieldCaptures`/`resolveFieldCaptures` verify, for a cancel/group binding stored into a named field of a keyed struct literal held by a single local variable, whether that same variable's field is later called (cancel) or `Add`/`Go`/`Wait`-called (group) elsewhere in the same function, rather than assuming the store itself discharged the obligation. `computeFieldOwnership` and `computeConstructorCallerConsumption` extend this one hop further, the same two-pre-pass shape `computeParameterConsumption` (Phase 5) already established, to the "constructor-returned handle" pattern: a function that stores a binding into a struct field and returns it is checked against its own direct, resolvable, same-package caller, regardless of which of the two is declared first in source. See `docs/limitations.md`'s aliasing paragraph for the exact, narrow boundary (a keyed literal assigned to a single named local variable or built directly in a `return`, one verified hop, no broader alias analysis) and `internal/frontend/frontend_test.go`'s `TestFieldCapture_*`/`TestFieldOwnership_*` tests for the covered positive/negative/fallback cases. The `Ownership` lattice itself remains unwired to real bindings, same as before — Phase 6's own note on `JoinObligation` applies here too: closing a real-world gap via a separate, more direct mechanism does not by itself retire the generic lattice, which stays available for a future alias-tracking effort that genuinely needs a block-level worklist solver rather than this identity-tracked, function-local (plus one verified hop) check.
4. **Done.** Model WaitGroup count intervals and common `Add`/`Done` imbalance patterns (Phase 6 of `docs/cfg-migration-plan.md`). `internal/frontend.computeGroupBalances` recognizes literal (or constant-folded) `Add`/`Done` counts outside loops and the common `Add(1)`-paired-with-a-spawned-`Done` idiom inside one, firing `LL1003`'s `CountMismatch` condition only from a positive, fully-accounted proof of imbalance. The same phase also added join-before-owner-return and stop-before-wait CFG checks (a new `model.CFG.ReachableAvoiding` primitive) and a new rule, `LL1005`, for the latter — see `docs/cfg-migration-plan.md` for the full description and `docs/limitations.md` for the stop-signal recognition's residual scope.
5. **Partially done.** Add generated-file, path, and source-annotation suppressions with auditable reasons. Generated-file detection, glob-based `ignore_paths`, and inline `//lifeline:ignore` comments are implemented (`docs/limitations.md`). Not yet done: a required, auditable *reason* string attached to a suppression (today's `//lifeline:ignore LL1002 -- reason` free text after `--` is not parsed or validated, just conventional).
6. Add phase-separated timing and cancellation accounting for package discovery, parsing, type checking, model/SSA construction, recognition, and rendering.
7. **Started.** Add property tests for model invariants and differential tests against a compact trusted control-flow implementation. `tests/differential/cfg_ast_test.go` compares the engine against `internal/cfg`'s reachability directly, including the former false negative loop-scoping alone couldn't close, now held as a passing regression fixture (`TestFixed_NestedLoopsMixedResolution`) rather than a documented gap. `internal/model/cfg_algorithms_test.go` covers the graph algorithms (`Reachable`, `CanReach`, `SCCs`) in isolation from AST translation, and `internal/model/dataflow_test.go` covers the generic worklist solver the same way — including a loop-propagation test that caught a real convergence bug (a block's first-ever computed value coinciding with the lattice's bottom was wrongly treated as "no change") before anything was built on the solver. No model-invariant property tests yet.
8. Expand corpus evaluation beyond `net/http`, including precision labels and unsupported-site counts.

## Optional feature expansion

1. **Partially done.** Signature-aware wrapper declarations with callback/result/receiver indices. `start_wrapper` callbacks and `context_wrapper` result roles (context vs. cancel function) are now resolved by static type rather than fixed position or explicit config, which covers the common cases without adding config surface; explicit receiver-index configuration is not implemented (see `docs/limitations.md` for what remains unconfigurable).
2. Rich editor fixes for context-select skeletons when insertion is structurally safe.
3. A persistent cache keyed by tool/fact versions, Go toolchain, build configuration, source/dependency digests, configuration digest, and backend mode.
4. A corpus runner that emits precision-review tables and minimized fixtures.
5. An optional full `golang.org/x/tools/go/ssa` backend for alias and call-graph experiments.
6. A formal backend interface when a second backend exists; avoid introducing an abstraction with only one implementation.

Correctness and trust tasks should be completed before broadening the default warning set.
