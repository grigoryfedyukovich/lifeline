# Roadmap

## Correctness and trust work

1. **Done.** Replace the may-exit loop heuristic with a compact control-flow graph that distinguishes loop, switch, select, and labeled breaks. `internal/cfg` builds and dumps (`-dump cfg`) this graph, and `LL1002` now evaluates it via `internal/engine/cfg_verdict.go`: a persistent (cyclic) strongly-connected component with no edge reaching the function's exit, judged independently per component. This now applies to cross-package `go vet` targets too (fact schema version 3, `FunctionFact.LoopUnresolved`), not only same-package/closure ones — see `docs/cfg-migration-plan.md` for the phased plan and current status, and `docs/architecture.md` for how it fits the rest of the codebase. `LL1003`/`LL1004`/`LL1005` read a CFG too now (Phase 6, item 4 below), via their own separate mechanism rather than this one. Not yet done: the generic CFG dataflow `JoinObligation`/`Ownership` lattices are still not exported as facts. Item 3 now exports a narrower constructor-return ownership summary for the supported field/handle shape, but there is still no general cross-package CFG-based ownership/join dataflow fact.
2. **Done.** Emit a low-noise user-visible `UNSUPPORTED` coverage outcome without turning every external goroutine target into a warning. Standalone text/JSON/SARIF output now distinguishes a clean result, a clean result with unsupported goroutine targets listed by file:line and reason, and a result where nothing lifecycle-relevant was recognized at all — see `docs/limitations.md`.
3. **Done**, via a direct frontend mechanism rather than by wiring up `internal/engine/dataflow_lattices.go`'s `Ownership` lattice. Track cancellation and group ownership through selected struct fields and constructor returns instead of treating every store as final discharge: `internal/frontend`'s `collectFieldCaptures`/`resolveFieldCaptures` verify, for a cancel/group binding stored into a named field of a keyed struct literal held by a single local variable, whether that same variable's field is later called (cancel) or `Add`/`Go`/`Wait`-called (group) elsewhere in the same function, rather than assuming the store itself discharged the obligation. `computeFieldOwnership` and `computeConstructorCallerConsumption` extend this to the "constructor-returned handle" pattern as a fixed point. Like `computeParameterEffects` (Phase 5), constructor propagation now uses a reverse-dependency worklist rather than whole-package sweeps, plus a callee-indexed returned-field table: a function that stores a binding into a struct field and returns it is checked against its own direct, resolvable, same-package caller, and a caller that itself just passes the handle on unconsumed is registered as a further, equally valid site, so only callers of that wrapper are revisited and a chain of any number of pass-through callers is verified regardless of declaration order. Both the "stored struct" and "constructor" shapes are also verified through a call to a same-package method on the handle, or the handle passed as a direct argument to a further same-package function (`followHandleMethod`/`followHandleArgument`, sharing one per-local-variable summary cache and cycle guard, `handleSummaryOf`) — a mix of method calls and function-argument hops, to a bounded depth, credits whatever the callee consumes on the handle's behalf back to the original call site, rather than the handle's being passed anywhere at all falling straight to assume-transferred. See `docs/limitations.md`'s aliasing paragraph for the exact, narrow boundary (a keyed literal assigned to a single named local variable or built directly in a `return`; an unnamed parameter, a `...` spread, or a variable reassigned more than once still falls back) and `internal/frontend/frontend_test.go`'s `TestFieldCapture_*`/`TestFieldOwnership_*` tests for the covered positive/negative/fallback cases. Cross-package constructor callers now use the same caller-attribution semantics for this supported shape: `ReturnFieldSite` facts carry a per-obligation ID plus the exporting constructor's final caller-discharge state, so a bad caller in another package gets LL1001/LL1003 at its own call site, a good caller remains clean, independent returned handles do not merge, and a local pass-through wrapper preserves the obligation. Fact schema version 6 makes this richer meaning explicit. The `Ownership` lattice itself remains unwired to real bindings, same as before — Phase 6's own note on `JoinObligation` applies here too: closing a real-world gap via a separate, more direct mechanism does not by itself retire the generic lattice, which stays available for a future alias-tracking effort that genuinely needs a block-level worklist solver rather than this identity-tracked, bounded-depth check.
4. **Done.** Model WaitGroup count intervals and common `Add`/`Done` imbalance patterns (Phase 6 of `docs/cfg-migration-plan.md`). `internal/frontend.computeGroupBalances` recognizes literal (or constant-folded) `Add`/`Done` counts outside loops and the common `Add(1)`-paired-with-a-spawned-`Done` idiom inside one, firing `LL1003`'s `CountMismatch` condition only from a positive, fully-accounted proof of imbalance. The same phase also added join-before-owner-return and stop-before-wait CFG checks (a new `model.CFG.ReachableAvoiding` primitive) and a new rule, `LL1005`, for the latter. F7's original function-wide signal pooling is gone: workers are correlated to their own context-derived stop sources, defer execution order is modeled, explicit nested local context-field paths are resolved back to their stored context objects for worker literals and visible same-package named workers, and channel-close shutdown is correlated when a worker clearly terminates on that channel (`select` receive + return, or channel range). Simple local channel aliases and explicit nested local channel-field paths resolve to the same canonical stop source on both receive and close sides, including composed named-worker argument prefixes. See `docs/cfg-migration-plan.md` for the full description and `docs/limitations.md` for the remaining heap/container-alias, promoted-selector, helper, and other-stop-mechanism boundaries.

   **F5 closure follow-up done.** Captured outer cancel/group effects are no longer credited merely because cleanup text appears inside a literal. Synchronous IIFEs and single-assignment stored literals are summarized in their own CFG and applied at the owner's invocation call site; conditional invocation/cleanup therefore remains conditional. Callback/go capture is represented as transfer where appropriate, and async Wait is not treated as owner-side join. Remaining function-value work is general callback contracts, function fields/reassignments, and package-level literals.
5. **Partially done.** Add generated-file, path, and source-annotation suppressions with auditable reasons. Generated-file detection, glob-based `ignore_paths`, and inline `//lifeline:ignore` comments are implemented (`docs/limitations.md`). Not yet done: a required, auditable *reason* string attached to a suppression (today's `//lifeline:ignore LL1002 -- reason` free text after `--` is not parsed or validated, just conventional).
6. **Started.** Add phase-separated timing and cancellation accounting for package discovery, parsing, type checking, model/SSA construction, recognition, and rendering. Cooperative cancellation now reaches frontend fixed points, AST walks, CFG construction, and local SSA-like construction. The main repeated-summary scans have also been reduced: parameter effects and constructor-return propagation use reverse-dependency worklists, all structural-CFG consumers share one cached immutable CFG/call-site index per body, and WaitGroup count/round accounting builds one per-function group-use index so each group skips unrelated statement subtrees and reuses a single top-level `Wait()` boundary index rather than rescanning the whole body to rediscover them. The flat local SSA-like IR is opt-in (`frontend.Input.CollectIR`) and is skipped by ordinary standalone/vet analysis. Standalone coverage aggregation now reserves one run-owned unsupported-target slice and merges package coverage into it in place instead of cloning the accumulated slice on every package. Package discovery also decodes `go list -json` directly from the subprocess stdout pipe with bounded stderr retention instead of buffering the complete JSON stream before decoding. Standalone package loading now reuses one run-wide compiler-export importer/type universe (with per-root `ImportMap` translation and independent root `types.Info` state), so shared dependencies are not re-decoded for every root. Frontend work counters now cover fixed-point evaluations, structural-CFG cache misses, and WaitGroup statement visits for CI scaling budgets. Still missing: phase-separated timers plus broader explicit node/edge/update and memory budgets for enforcing resource ceilings rather than only detecting algorithmic regressions.
7. **Started.** Add property tests for model invariants and differential tests against a compact trusted control-flow implementation. `tests/differential/cfg_ast_test.go` compares the engine against `internal/cfg`'s reachability directly, including the former false negative loop-scoping alone couldn't close, now held as a passing regression fixture (`TestFixed_NestedLoopsMixedResolution`) rather than a documented gap. `internal/model/cfg_algorithms_test.go` covers the graph algorithms (`Reachable`, `CanReach`, `SCCs`) in isolation from AST translation, and `internal/model/dataflow_test.go` covers the generic worklist solver the same way — including a loop-propagation test that caught a real convergence bug (a block's first-ever computed value coinciding with the lattice's bottom was wrongly treated as "no change") before anything was built on the solver. No model-invariant property tests yet.
8. **Started.** Expand validation beyond the old `net/http` smoke record. `internal/frontend/benchmark_test.go` provides reproducible synthetic frontend benchmarks for caller-first parameter-delegation chains, constructor-forwarding chains, and many independent WaitGroups; `make bench` runs them with allocation reporting. The fixtures are type-checked once outside the timer so the numbers measure Lifeline frontend/model work rather than Go parsing/importing. Repository reproducibility is checked too: `go.sum` is committed, `make modcheck` runs `go mod tidy -diff`, and `.github/workflows/ci.yml` uses the `go.mod` toolchain to run module verification, tests/vet, race detection, work-budget checks, a benchmark smoke run, and a standalone build. **Machine-independent performance budgets are now enforced:** optional `frontend.Input.WorkStats` counters measure fixed-point evaluations, structural-CFG cache misses, and WaitGroup statement visits; `TestFrontendWorkBudgets`/`make perfcheck` cap the adversarial fixtures at linear work so a future reintroduction of whole-package rescans fails CI independent of runner speed. Still missing: a supported-Go-1.25 elapsed-time/allocation/RSS baseline committed to `docs/evaluation.md` and a pinned real-project corpus with independently reviewed precision/unsupported labels.

## Optional feature expansion

1. **Partially done.** Signature-aware wrapper declarations with callback/result/receiver indices. `start_wrapper` callbacks and `context_wrapper` result roles (context vs. cancel function) are now resolved by static type rather than fixed position or explicit config, which covers the common cases without adding config surface; explicit receiver-index configuration is not implemented (see `docs/limitations.md` for what remains unconfigurable).
2. Rich editor fixes for context-select skeletons when insertion is structurally safe.
3. A persistent cache keyed by tool/fact versions, Go toolchain, build configuration, source/dependency digests, configuration digest, and backend mode.
4. A corpus runner that emits precision-review tables and minimized fixtures.
5. An optional full `golang.org/x/tools/go/ssa` backend for alias and call-graph experiments.
6. A formal backend interface when a second backend exists; avoid introducing an abstraction with only one implementation.

Correctness and trust tasks should be completed before broadening the default warning set.
